# 실제 ISA 이미지 OCR 검증

## 범위와 재현

운영 배포 전 PR #2 소스를 기준으로, 사용자가 제공한 실제 ISA 캡처 2장을 로컬 브라우저 업로드 UI에서 검사했다.
원본·OCR 원문·계좌번호·실제 보유 수량/매입가 기대값은 Git에 넣지 않았다. 기대값은 저장소 밖 비공개 임시 파일에서만 비교했다.

- 환경: Debian 13, Chromium 156.0.8078.79, 모바일 viewport 344×882.
- 실제 OCR: Tesseract.js 5.1.1, 기본 `kor+eng` 인식.
- 실행 경로: 파일 선택 → 업로드 버튼 → 실제 OCR → 좌표 파싱 → 마스터 정확 일치 → 사용자 확인 → 모바일 편집.
- 저장 API는 **mock**이다. 이번 변경에서 실제 NH/GAS는 호출하거나 배포하지 않았다.
- 기존 fixture 재생 브라우저 테스트와 이번 실제 이미지 OCR 테스트는 별도 실행이다.

변경 전 실제 이미지 두 장 모두 머리글 인식 실패로 0종목이었다. OCR이 머리글/한글 이름을 여러 단어로 분할했고 `종목명` 일부 글자를 누락했다.
좌표로 머리글 조각을 결합하고, 두 단 머리글의 같은 열을 하나의 경계로 처리했다. `매입가`를 지원하고, 수익률/현재가 하단 행의 숫자는 수량/매입가로 가져오지 않는다.

영문·한글 혼합 종목명 한 셀은 기본 OCR이 일부 문자를 누락했다. 불확실한 이름 셀만 2배 확대하여 한국어와 영어 단일 행 모드로 각각 읽는다.
영어 접두부(문자 신뢰도 90 이상)와 한글 접미부(80 이상)의 겹치지 않는 문자 좌표/인접성/같은 행을 확인한 뒤, 결합한 전체 이름이 마스터에 정확히 일치할 때만 채택한다.
특정 종목의 별칭·코드 하드코딩이나 퍼지 이름 추측은 없다. 조건 미충족/추가 인식 실패 시 원래 후보를 확인 필요 상태로 남긴다.

## 결과

| 항목 | 실제 이미지 결과 |
| --- | --- |
| 2장 통합 종목 수 | 정확히 7개 |
| 7개 수량·평균매입가 | 원본과 전부 일치 |
| 7개 이름·종목코드 | 마스터와 전부 정확히 일치 |
| 현금/가짜 종목/중복 | 각각 0개 |
| 모바일 결과 수정 | 통과 |
| 확인 후 저장 | mock 저장 API로 통과 |
| 인식 실패 시 기존 목록 보존 | 별도 mock 실패 주입으로 통과 |

기존 ISA/연금저축/IRP fixture 브라우저 3개, OCR/매칭 단위 15개, 기존 시세/프런트엔드 회귀 19개도 통과했다.
이번 두 이미지에서 남은 인식 오류는 없다. 다른 화면 배치, 흐릿한 캡처, 실제 Fold6 기기에서의 성능, 실제 OCR 결과의 운영 GAS 저장은 별도 미검증이다.

## 비공개 원본으로 재실행

이미지 2장과 기대값 JSON 배열을 저장소 밖에 둔다. 기대값 필드는 `name`, `code`, `quantity`, `avgPrice`다.

```bash
CHROMIUM_EXECUTABLE=/usr/bin/chromium python3 tests/browser_real_ocr.py \
  --images /private/isa-a.jpg /private/isa-b.jpg \
  --expected /private/expected.json
```

원본은 브라우저 내에서만 처리한다. 외부 요청은 OCR 실행 파일/언어 모델 다운로드이며, 금융 데이터를 보내지 않는다.
테스트는 OCR 원문·금융값·DOM·스크린샷·trace를 출력/업로드하지 않고 안전한 통과 여부만 출력한다.
이 테스트는 비공개 입력이 필요하므로 공용 CI에서 fixture 테스트로 대체하거나 실제 이미지 검증 성공으로 표시하지 않는다.

main 병합과 운영 GAS 배포는 사용자 승인 전 금지다. 임시 캡처/실제 OCR 원문을 PR 첨부물로 게시하지 않는다.
