# 보안 수정 내역

## 확인한 문제와 변경

- 비밀번호 평문 저장: 신규 계정과 로그인에 성공한 기존 계정은 사용자별 무작위 salt를 사용하는 PBKDF2-SHA256(600,000회)으로 저장합니다. 로그인하지 않은 기존 행은 아직 이전 저장 방식으로 남아 있으므로, 시트 접근권한도 제한해야 합니다.
- 고정 초기 관리자 비밀번호: 자동 관리자 생성 코드를 제거하고, 이전 기본 관리자 비밀번호로 로그인하는 것도 차단합니다. 해당 비밀번호를 사용 중이면 소유자가 비공개 Users 시트에서 12자 이상 새 비밀번호를 설정하고 로그인해야 합니다. 이후 자동 해시 전환됩니다.
- 로그인 추측: 계정별 15분 동안 최대 8회 시도로 제한합니다. 신규 비밀번호는 12~256자입니다.
- 관리자 목록의 저장형 XSS: 회원 정보를 HTML/인라인 JavaScript 문자열로 조립하지 않고 DOM의 textContent와 이벤트 핸들러로 표시합니다. 보유종목명과 뉴스 링크도 안전하게 표시합니다.
- 이전 사용자 데이터 노출: 로그아웃 시 잔고·외부계좌·보유목록·OCR·자동갱신을 정리하고, 세션이 바뀐 뒤 도착한 응답과 OCR 결과를 무시합니다. 세션 복원 시 서버 권한을 다시 확인합니다.
- 세션 및 권한: 서버에서 승인 상태를 확인하고 5분 유휴·8시간 절대 만료를 적용합니다. 이전 형식 세션은 다시 로그인해야 합니다. 소유자 NH 잔고와 이전 고정 보유목록은 관리자만 조회합니다.
- Sheets 수식 입력·잘못된 저장: 회원 ID, 종목코드, 수량, 매입가, 수식으로 해석될 문자열을 검증하고 잘못된 요청은 전체 저장 전에 거부합니다. 저장 작업은 잠금으로 직렬화합니다.
- 프록시 URL: HTTPS와 기존 허용 도메인만 인정하고, 다른 도메인으로의 리다이렉트 추적을 막습니다. 로그인 주소도 Google Apps Script HTTPS 웹 앱 형태로 제한합니다.
- 공개 기본 보유목록: 수량·매입가는 비공개 GAS의 SecurityData 파일로 보존하고 관리자 로그인 후 API로 불러옵니다. 공개 최신 data.js에서는 제거합니다. 이미 공개된 과거 Git 이력은 자동으로 삭제하지 않습니다. 실제 자료였다면 과거 공개 노출 가능성이 남습니다.

## 배포와 복구

GitHub Actions의 `Deploy verified Nhplug to Google Apps Script`를 main에서 실행합니다.
인증정보는 Actions Secret `CLASPRC_JSON`에만 보관합니다. 비공개 Code.gs·manifest·보유자료는
작업 서버 메모리에서 보존하며 공개 Git, 로그, 아티팩트로 내보내지 않습니다.

배포 전에 복구용 불변 버전을 만들고, 다른 파일에 배포되지 않은 편집이 있으면 중단합니다.
보안 변경은 Code.gs의 기존 진입점·인증 함수를 점검한 뒤 변환하고 Security/SecurityKdf를 추가합니다.
새 버전의 내용과 기존 배포 ID·주소를 확인합니다. 검증 실패 시 작업 전 버전으로 복구합니다.

SecurityKdf.gs는 MIT 라이선스의 `@noble/hashes@1.8.0`에서 SHA256/PBKDF2만 번들한 파일입니다.
원본 라이선스는 `gas/vendor/LICENSE.noble-hashes`에 보존했습니다.
표준 Node PBKDF2와의 결과 일치 및 GAS와 유사한 Node 없는 실행 환경을 테스트합니다.

이 변경은 확인한 문제를 보완합니다. 이후 수정에서도 인증·권한·민감정보 노출을 계속 점검합니다.
