# MY INVEST V2 — 개발용 세션 1시간 정책 (독립 변경안)

## 요청과 현재 상태

사용자가 2026-11-21 개발 사이트의 5분 세션 때문에 작업이 끊긴다고 보고하고 **개발 세션 1시간**을 요청했다.

- 개발 브랜치: `feat/dev-hour-session-isolated` (Codex 작업과 분리)
- 화면: `js/auth.js`에서 `MYINVEST_TRANSPORT_CONFIG.devSession===true`일 때 **유휴 60분**, 기본 운영 화면은 **유휴 5분**
- 서버: `gas/Security.gs`에서 스테이징 바인딩/검증 메타데이터에 명시된 **격리 GAS만 유휴 60분**, 기본 운영 GAS는 유휴 5분 유지
- 서버의 **절대 만료 8시간**은 변경 없음. 명시적 로그아웃, 승인 취소, 비밀번호 변경에 따른 토큰 무효화도 변경 없음.
- 개발 프런트는 별도 탭 저장소를 사용하며 운영 저장소와 세션을 공유하지 않음.

## 중요한 구분

소스 수정만으로 현재 공개 개발 사이트의 서버 세션은 늘어나지 않는다. 실제 사용자가 1시간을 이용하려면 **검증된 격리 staging GAS**에 해당 Security.gs 변경사항을 배포하고, 안정적인 Codex 작업 종료 시점에 맞춰 **개발 전용 GitHub Pages만** 안전 게시해야 한다.

한쪽만 수정하면 화면은 1시간을 표시하면서 서버 인증이 5분에 만료되어 실제 사용에 문제가 생긴다. 임시 화면용 1시간 타이머 단독 게시 금지.

운영 GAS, 운영 Pages, 운영 Sheets/Properties, 프로덕션 Worker 설정의 변경은 절대 하지 않는다.

## 보안 검증

- `securityEnvironmentGuard_`와 `securityEnvironmentMetadata_`가 둘 다 존재해야 함.
- `freshTestEnvironment:true`, `testEnvironment:'nh-staging'`, `gatewayVersion:2`, `storeEngine:'account-store-v2'` 및 세 개의 64자리 지문이 모두 확인되는 격리 환경에서만 60분 적용.
- 위 조건 하나라도 불일치 또는 메타데이터 오류가 발생하면 5분으로 되돌아감 (fail closed).
- 실제 환경에서는 변경 전후 원격 소스 지문, 디플로이먼트 버전, 로그인/세션 API 결과를 검증해야 함.
- 신뢰되지 않는 신호를 근거로 운영 환경 세션을 연장하지 않음.

## 검증/출시 전 확인

1. 새 `tests/dev-hour-session.test.cjs`에서 개발 클라이언트/서버 60분, 운영 5분, 스테이징 메타데이터 실패 시 5분, 절대 8시간 체크.
2. 기존 `tests/security.test.cjs`, `tests/dev-session.test.cjs`와 전체 회귀 통과.
3. 실제 격리 스테이징 GAS 소스·배포 지문과 브라우저 현황을 별도 확인; 사용자가 명시적으로 요구한 변경 대상 이외의 GAS/Worker 변경 금지.
4. Codex의 현재 실데이터/RELAY_BUSY 수정 작업 완료 후 파일 충돌 없는 통합·배포 계획 점검.
5. 합성 검증 통과와 실제 60분 서버 세션 검증을 구분. 실제 60분 유휴는 검증 중 서버 인증 없이 비활동 상태를 유지한 뒤 다시 `sessionInfo` 요청이 성공하는지로 확인.
6. 배포 후 동일 조건에서 60분 초과 만료, 개발용 명시적 로그아웃, 운영 환경 5분 만료, 최대 8시간을 확인.
7. 추가 갱신/heartbeat 호출을 도입하지 않아 RELAY_BUSY 개선과 경쟁하는 요청을 늘리지 않음.

## Codex 작업 보류

현재 진행 중인 Codex의 중계/실데이터 장애 해결을 방해하지 않는다. 사용자가 추후 "코덱스 지시문 작성"을 요청하면 이 문서 및 그때의 완료 상태를 참고하여 **스테이징 GAS와 개발 Pages 양쪽의 일치된 게시/실환경 검증만** 과제에 반영한다. 그 전에는 지시문을 새로 발송하지 않는다.
