# Issue #1: 외부계좌 OCR·종목 매칭·복구

## 동작

- OCR 좌표와 머리글을 이용해 같은 물리적 행의 종목명·수량·평균매입가를 추출합니다. 계좌번호/메뉴/매수구분 `현금`은 제외합니다. 좌표·머리글이 없으면 추측하지 않습니다.
- 현금성 상품은 전체 종목명이 상장 마스터와 일치하는 경우에만 검증합니다. 비상장 CMA/RP/MMF 등 미확인 상품에는 코드를 추측하지 않습니다.
- 하드코딩 코드와 `YHA → 크레버스`, `KCC2atA → KCC글라스` 같은 추측 보정을 제거했습니다. 미일치·중복 이름·기존 코드 충돌은 확인 필요입니다.
- KRX의 영문 혼합 6자리 코드도 유지합니다. 예: 에스엔시스 `0008Z0`. 숫자만 남기거나 7자리 값을 잘라 다른 코드로 만들지 않습니다.
- 이미 저장된 행은 읽기/렌더 단계에서 삭제·정정하지 않습니다. 마스터 코드 적용, OCR 덮어쓰기, 실제 저장, 복원에 각각 확인이 필요합니다. 중복 캡처는 수량을 더하지 않습니다.
- 임시 편집/삭제 취소는 메모리에 최대 10회, 실제 저장/삭제/복원 이전 상태는 사용자별 서버 기록에 최대 5개 보관합니다. 로그아웃하면 브라우저의 해당 자료는 지웁니다.
- 저장은 사용자별 revision으로 충돌을 검사합니다. 저장 실패 시 해당 사용자 행만 복구하고, 자동 복구도 실패하면 복구 기록 ID와 명확한 실패 상태를 반환합니다.
- 프런트엔드 전송 실패, GAS HTTP/JSON/인증 오류, NH HTTP/rsp_cd/가격 필드/다른 종목 응답을 분리합니다. 비밀정보가 포함될 수 있는 원문 예외·응답 본문은 표시하지 않습니다.
- 확인되지 않은 가격은 null/`시세 미확인`/`—`로 남기고 평가액·손익에서 제외합니다. 확인한 종목만 부분 합계로 표시합니다. 일반계좌 국내/해외 잔고 호출 경로와 입력은 변경하지 않았습니다.

## 종목 마스터 출처와 갱신

현재 스냅샷: 주식 2,724개 + ETF 1,191개 = 3,915개. 기준일은 JSON의 `source.fetchedAt`입니다.

KRX 직접 데이터 요청은 로그인 요구(`LOGOUT`, HTTP 400) 응답이었습니다. **이 파일은 직접 KRX API 응답이 아니라 한국투자증권이 공식 배포하는 KRX 상장종목 마스터**입니다.

- https://new.real.download.dws.co.kr/common/master/kospi_code.mst.zip
- https://new.real.download.dws.co.kr/common/master/kosdaq_code.mst.zip
- 형식 참고: https://github.com/koreainvestment/open-trading-api/tree/main/stocks_info

원본 archive SHA256과 공급자·수집시각을 JSON에 기록합니다. TLS 검증을 끄지 않습니다.
ST/EF 그룹의 정확한 6자리 영문/숫자 코드를 보존하며 ETN·워런트 등 다른 그룹은 포함하지 않습니다.
30일이 지난 마스터는 자동 매칭·시세 계산에 사용하지 않고 갱신 필요로 표시합니다.

```bash
python3 tools/update_instrument_master.py
```

갱신은 파일 원자 교체로 처리하며 잘린 파일·중복 코드·불완전 시장 범위는 거부합니다.
마스터 갱신도 별도 PR로 검토합니다. 신규/변경/상장폐지 종목과 이름 충돌을 확인하세요.

## 테스트와 검증 범위

로컬 결과: Node 61개 + Python 22개 = **83개** 통과. 별도로 ISA/연금저축/IRP 모바일 브라우저 흐름 3개 통과.

```bash
for file in tests/*.test.cjs; do node "$file" || exit 1; done
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/browser_external.py
```

- ISA 7종목 fixture에는 에스엔시스 `0008Z0`, 현금 행, 메뉴, 합성 계좌 헤더, 중복 캡처가 포함됩니다. 모든 수량·매입가는 합성값입니다.
- 연금저축/IRP fixture는 ETF·현금성 ETF를 포함합니다. 인접 행 숫자 오연결, 미일치/모호한 이름, 코드 충돌, 머리글 누락을 테스트합니다.
- 브라우저는 Tesseract 인식 결과와 GAS/NH를 mock합니다. 업로드→비교/확인→중복 방지→삭제 취소→저장/복원→진단→로그아웃까지 검사합니다.
- 일반계좌는 국내/해외 응답, 연속조회 헤더, 모의/비대상 계좌 제외, 해외 장애 시 국내 결과 보존, 비로그인 차단을 mock으로 확인합니다.
- **실제 NH 계좌·시세 API, 운영 GAS, 실제 휴대폰 캡처 인식률은 이번 PR에서 테스트하지 않았습니다.** 실제 OCR 엔진의 인식률과 NH 연동 성공은 승인 후 비식별 자료와 사용자 로그인 환경에서 확인해야 합니다.

## GAS 영향과 승인 후 적용/복구

새 GAS 파일 `ExternalHoldings.gs`가 필요합니다. `Security.gs`에서 외부계좌 저장/조회/복원 요청을 새 처리기로 연결합니다.
기존 ExternalHoldings 8열은 유지하고, ExternalHoldingHistory 6열을 별도로 만듭니다. 사용자별 소유권을 검증합니다.
새 클라이언트는 revision이 없는 구버전 GAS에 저장을 요청하지 않습니다. 따라서 승인/배포 전 기존 자료를 맹목적으로 교체하지 않습니다.

이 PR은 main 병합·운영 배포를 수행하지 않습니다. 승인 후 main 병합과 별도의 수동 GAS 배포가 필요합니다.
운영 배포 전 복구 버전을 생성하는 기존 절차는 유지합니다. 코드 롤백은 기존 GAS 배포 버전 복원으로,
보유목록 롤백은 사용자별 저장 복구 기록으로 처리합니다. 코드 롤백만으로 Sheets 변경이 되돌아가지는 않습니다.

기본 회귀 CI에는 Google/NH secrets가 없습니다. 별도 `nh-staging` 환경 승인·설정 후에만 실제 연동 job을 활성화할 수 있습니다. 현재 실제 테스트는 환경 미설정으로 BLOCKED입니다. 절차와 결과는 [NH_STAGING_TEST.md](NH_STAGING_TEST.md)를 참고하세요. 실패는 PR 체크에 표시됩니다. 현재 main은 보호 브랜치가 아니므로,
GitHub 차원의 병합 강제 차단을 원하면 관리자가 `PR regression tests / regression`을 필수 체크로 지정해야 합니다.
이번 작업에서는 저장소 보호 규칙을 변경하지 않았습니다.
