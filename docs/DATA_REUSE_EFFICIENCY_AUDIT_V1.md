### 현 단계의 결론

**조회 결과 재사용을 보장하는 공통 스키마가 아직 없음.** 각 화면이 자체 Map·계약을 사용한다. `GET /...chart/SERV?interval=1d&range=1y`처럼 같은 자산·기간을 다시 요청할 가능성이 있다. 실제 재요청 횟수는 모의 브라우저 네트워크 호출 집계로 검증해야 한다.

## 권장 정책 (다음 통합 단계 우선순위)

**1. 동일 데이터 원천에 대한 단일 소유자 선택**

- 기존 `DashboardTransport.publicRead(url)`와 `getJSON(url)`이 결국 접근하는 단일 공개 URL 경로에 공통 읽기 캐시/진행 중 요청 병합을 **한 번만** 배치한다. 추가로 산업/리포트 각각 새 캐시를 만들지 않는다.
- 인증·계좌·NH 주문·GAS 비공개 요청은 절대 공통 공용시세 캐시에 넣지 않는다.
- 캐시 키는 `정확한 정규화 URL + 시장·거래소·티커 + interval/range + 공개 데이터 증거 프로필 + 세션 세대`로 구분한다. `SPY`와 `^GSPC`, `.KS`와 `.KQ`, USD와 KRW, 원천 변경을 섞지 않는다.

**2. 새 조회 전의 4단계 결정**

```text
기능이 데이터 요청
  → (1) 기존 Home Q / InvestWorkflow.analyses / Sector analytics / IndustryData 수신 자료 중
        식별자·출처·시장·시각·범위가 맞는 완료 결과가 있으면 재사용
  → (2) 동일 캐시 키의 요청이 진행 중이면 새 HTTP 없이 기존 Promise 공유
  → (3) 일부 필드만 부족하면 *부족한 원천·범위*만 추가 조회
  → (4) 명시적 사용자 강제 갱신이거나 관측·수신 최신성 초과 시 해당 키만 무효화 후 재조회
```

**3. 캐시 정책 정교화**

- 현재 종목분석 기본 동작의 `ensure(..., true)`를 자동 사용자 진입·종목 전환 시에는 재사용 우선으로 바꾸고, 사용자가 직접 누른 '새로고침'에서만 force=true를 전달한다. 단, 기존 종목 분석 UI 로딩·조건부 전략이 이상 없는지 종합 회귀 확인 후 반영한다.
- 시장 장중 짧은 TTL과 장 마감 확정 일봉의 TTL을 분리하되, 원천 관측시각이 없는 자료는 장 마감으로 간주하지 않는다.
- 과거 1년치 일봉 데이터는 단일 정규화 원천 응답을 받아 1/5/20/60거래일 수익률 등으로 재계산하여 사용한다. 조회를 4회로 분할하지 않는다.
- 현재 `reload()`의 전체 `SERIES_CACHE.clear()`는 전체 타 종목 캐시까지 폐기한다. 사용자 새로고침 대상/시장·산업별 관련 키만 폐기하는 방안을 별도 검증한다.
- 인증 로그아웃·개발 릴레이 교체·시장데이터 원천 변경·가격 보정/분할 확인 시 해당 키를 반드시 폐기하고, stale 결과를 최신값으로 표기하지 않는다.
- 조회 실패 시 최근 성공한 결과가 있어도 '과거 관측값'으로만 표시하고 자동 실시간 거래 판단에 사용하지 않는다.

**4. 요청 예산·관측 및 회귀 완료 기준**

- 동일 URL의 동시에 두 개 화면 요청은 물리 원천 조회 **최대 1회** (세션·signal 정책 조건 충족).
- 적격 캐시가 살아 있는 동안 동일 종목의 종목분석 → 전략 이동은 원칙적으로 **추가 시계열 조회 0회**.
- 5분 캐시 내 종목분석 재방문/유효한 캐시에서는 다시 1년치 원본 요청 0회, 사용자가 명시한 새로고침에서만 추가 요청.
- 산업 페이지에서 수신된 동일 Yahoo 1년치 종목 일봉이 `publicAnalysis`에 필요한 필드(OHLCV, 식별자, 거래소, 통화)를 모두 충족할 때만 재사용. 기존 `page-sectors`의 가공된 `bars/times/volume`에는 OHLCV 중 open/high/low가 빠져 **단순히 캐시만 전달해서 전략 분석할 수 없음**.
- 1일 실시간 지수 vs 1년 일봉, 대리지표 vs 구성종목 전체, 5/20/60일 분포는 서로 동일 데이터 계약이 아님.
- 네트워크 로그에서 `총 요청·원천 URL별 실조회 수·캐시 적중·진행 중 합류·강제갱신·실패 재시도·지수/섹터 전환`을 집계하되 토큰·계좌·인증헤더/원문 응답은 기록하지 않는다.

## 이번 독립 개발과 연결 범위

- `js/research-native-data-contract-audit-v1.js`는 기존 Home/산업/국내구성종목/종목분석 *반환 객체*만 받아 각 단계가 실리포트 입력 계약을 충족하는지 판단. API/계좌/주문 호출 **0회**.
- `js/research-native-contract-audit-panel-v1.js`는 임시 개발 검증 화면에서 원천 불일치 및 미충족 사유만 표시.
- 아직 공통 공개 데이터 캐시를 실제 앱에 연결하거나, 종목분석 `force=true`를 수정한 것은 아니다. 검증이 끝나고 코덱스 통합 변경과 충돌 여부를 검토한 뒤 별도 안전 패치가 필요.
